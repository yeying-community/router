# 账务核算标准

> 适用范围:router 的上游成本 / 下游收入 / 盈利核算 / 定价。本文是基线规范与迭代判据,不是实现细节。
> 配套:[渠道规范](../模型渠道/渠道规范.md)、[接口契约说明](../接口契约/接口契约说明.md)。

## 0. 北极星与判据

**唯一目标**:把**上游成本**与**下游收入**统一到同一记账口径,算出**盈利**,并据此**合理调价**。

**判据(每个账务相关功能都要过这一关)**:*它能否让 router 更准、更可信地算出利润,或据此更合理地调价?* 不能的,就不做、或删掉。

记录余额、权益、采购等信息,都是手段;手段不服务于上面这句话,就是负债。

---

## 1. 现状基线(已具备 vs 缺口)

诚实盘点(均有代码依据),作为迭代起点:

**已具备**
- **YYC 币种目录**:`billing_currencies` 表以 `charge_rate`(YYC/单位)把任意币种归一到 YYC(YYC=1.0、USD=500000、CNY≈71428)。
- **按模型成本**:采购批次有 `scope_type=model|global`,模型域优先于全局回退(消费排序已保证)。
- **多级置信**:`cost_source`、`cost_status`、`readiness`、`attribution status`、`settlement truth`、`cost confidence` 六套枚举已存在。
- **毛利核算**:每请求 `gross_profit = sell − cost`、`margin`,有采购/盈利报表。

**缺口 / 问题(即"假设撑不住迭代"的具体表现)**
1. **双币种割裂**:下游收入记为 **YYC**(`charge_amount`),上游成本/毛利却记为 **CNY base**(`cost_base_amount`)。与"都换算成 yyc"的目标不一致。
2. **反腐层对错了名词**:billing 服务 `:query` 返回的是**余额/权益快照**,不含成本。真正服务目标的"成本归一"却埋在 router 内部。
3. **定价与成本脱钩**:下游价=list×ratio,**手动**设置;成本→价的 cost floor 公式存在但**默认关**(margin=buffer=0)、且仅 CNY。
4. **置信枚举过载**:六套枚举分别描述相近的事,边界不清,难推理——典型的"加一个需求就打补丁"。
5. **余额子系统过重且基本没用**:「权益项/计费形态/多额度类型」投入很大,对盈利核算却是辅助。
6. **一表两用**:`channel_billing_snapshots` 同时当"余额观测"和"采购记录",靠 `source_type` 区分——最大的纠缠源。

## 2. 记账单位标准

- **YYC = 操作记账单位**:凡进入"毛利 / 定价"决策的量,必须能表达为 YYC;与下游收费口径一致,支持跨渠道、跨模型比较。
- **法币(CNY/USD)= 实盘 P&L 与 FX 审计子账**:保留真实付款数额与汇率,用于看真金白银盈亏与汇率敞口,但**不作为跨渠道比较口径**。
- **规定**:解决现状的双币种割裂——成本必须能经 `charge_rate` 归一到 YYC;毛利/报表**同时给出 YYC 与法币两列**。YYC 为主口径,法币为审计。

---

## 3. 成本口径契约(基线)

账务的脊柱是"每个 (渠道, 模型, 计量单位) 的归一化单位成本",即 **CostQuote**:

```
CostQuote {
  channel, model, capacity_unit        # 计量口径(如 per_1k_tokens / per_image / <currency>_equivalent)
  unit_cost_yyc                         # 归一后的单位成本(YYC)——定价/毛利只认这个
  unit_cost_fiat, currency, fx_rate, as_of   # 审计:原始法币单位成本、汇率、取数时间
  confidence                            # 置信等级(见 §4)
  scope        = model | global         # model 优先,global 回退
  valid_window                          # 生效 / 过期
}
```

- **成本必须按模型解析**:解析顺序 model-scope → global 回退(代码已支持)。定价与毛利一律基于 CostQuote,不得直接读裸价。
- **永不把未知成本伪造为 0**(沿用既有原则):无可用 quote = `unconfigured`,毛利不可算,如实标记;只有显式"免费"才是 `zero_cost`(单位成本 0)。

---

## 4. 置信度统一阶梯

把六套重叠枚举收敛为**两个正交的轴** + 一个生命周期维度,新代码只引用这套语义:

- **轴 A — 成本基准可信度**(成本数值有多可信):`actual` > `zero_cost` > `estimated` > `unconfigured/none`。
- **轴 B — 用量可信度**(消耗量有多可信):`returned_usage` > `hybrid_usage` > `local_estimate` > `unit_based` > `unmetered`。
- **一笔归因的总置信 = min(轴 A, 轴 B)**。
- **生产级**(可进利润结算 / 发布门槛 / 自动调价)= 轴 A ∈ {actual, zero_cost} 且批次 `active`,且轴 B ≥ `local_estimate`。
- **`cost_status`(active/exhausted/expired/disabled)是生命周期,不是置信**,禁止与轴 A/B 混用。
- **`readiness`(ready/missing/estimated/…/untracked)是上述两轴在"模型就绪"视角下的投影**,不是第七套独立枚举;不得再新增并列枚举。

---

## 5. 定价闭环(把成本用起来)

- **现状**:价=list×ratio,手动;cost floor 默认关、仅 CNY。
- **标准**:定价必须**可由成本驱动**——按模型的目标毛利策略
  `price_yyc = cost_yyc × (1 + risk_buffer) / (1 − target_margin)`。
  cost floor 从"默认关的兜底"升级为**一等定价输入**(健康检查 `pricing_policy_no_margin` 已存在,说明方向认可)。
- **置信门控**:`unconfigured` 成本**不得用于自动调价**(只能人工决定);只有生产级成本可驱动自动定价。

---

## 6. 余额 / 权益(降级为运营信号)

- **定位**:只服务两件运营事——① 快用完提醒充值(告警);② 对账(上游用量 vs router 计量)。**不参与利润核算。**
- **手工维护余额 = 移除候选**:确认无实际使用后,删除其作为"余额来源"的角色,消除 snapshot 一表两用的最大纠缠。
- **采购记录从"余额"解绑,归入成本账**:采购记录("花了多少、买了多少")只为生成 §3 的 CostQuote 服务,不再兼任余额来源。

---

## 7. billing 服务契约(反腐层对准成本)

- **现状**:`:query` 返回 `ChannelBillingSnapshotItem`(余额/权益),不含成本;服务可选(`base_url` 空 = manual)。
- **标准**:服务的**基线契约应产出 §3 的 CostQuote**,把各家预付/后付/阶梯/套餐差异屏蔽在服务内部;**余额作为可选 capability**。
- 服务可选性保留;一旦接入,router 优先消费其 CostQuote,自己不再为每家上游写特例。

---

## 8. 不变量(写新账务代码的红线)

1. **一个枚举只表达一件事**——枚举不是多义开关(反例:`billing_source=manual` 同时表示"没适配器/手工记/未配置")。
2. **UI 边界跟领域边界走,不跟表结构走**(上游账户 / 成本与采购 是两本账)。
3. **YYC 是利润与定价的单一口径**,法币仅审计。
4. **成本按模型;永不伪造 0 成本。**
5. **没接线的假设就删**(如已删除的 `enabled`/`profile_enabled`)。

## 附录 A:billing 服务 CostQuote 契约(P5 规格)

> P5 需同时改 router 侧消费与 billing 服务侧实现;服务代码在独立仓库。本附录只定**契约与消费语义**,作为服务侧实现的目标;在服务未实现前,router 维持现有本地采购成本路径,不写投机代码(遵守 §8「死假设就删」)。

### A.1 能力协商

`GET /api/v1/internal/adapters` 的 `billingServiceAdapterInfo.capabilities` 扩展两个标识:

- `balance_query`:支持返回上游余额/权益快照(即现有 `:query`,对应 §6 的运营信号)。
- `cost_quote`:支持返回归一化成本(本契约)。

router 按能力选择端点:有 `cost_quote` → 消费成本契约;否则仅余额(或纯本地采购成本)。两者都是**可选**,互不依赖。

### A.2 请求 `POST /api/v1/internal/billing:cost`

```
{
  "channel_id": "<id>",
  "adapter": "<name>",
  "credentials": { ... },          // 同 :query,服务侧解密/鉴权
  "models": ["<model>", ...]        // 可选;空=该渠道全部可解析模型
}
```

### A.3 响应:一组 CostQuote

```
{
  "quotes": [{
    "model": "<model>",            // 省略=渠道级(global 回退)
    "capacity_unit": "per_1k_tokens | per_image | <currency>_equivalent",
    "unit_cost": 0.0,              // 单位成本,币种见下
    "currency": "USD | CNY | ...", // 原始法币;router 经 charge_rate 归一到 YYC
    "as_of": 1739000000,          // 取数时间(秒)
    "confidence": "actual | estimated | unconfigured",   // 映射 §4 轴A
    "valid_until": 0               // 可选;0=长期
  }, ...]
}
```

**映射到现有模型**:`confidence` 直接对应 §4 轴 A 的成本来源(`actual`/`estimated`/`unconfigured`);`currency+unit_cost` 经 `BillingCurrency.ChargeRate` 归一为 YYC(与 P3 一致);`capacity_unit` 复用 `channelModelProcurementCapacityUnits` 口径。服务把各家预付/后付/阶梯/套餐差异**在内部**折算成单位成本,router 不再写上游特例。

### A.4 router 消费语义(服务实现后再落地)

1. **优先级**:同一 `(channel, model)` 若服务返回 `confidence=actual` 的 CostQuote,优先于本地采购批次估算;服务 `estimated/unconfigured` 或无返回 → 回退本地采购成本(§3)。永不因服务缺数而把未知成本当 0(§8)。
2. **置信门控**:只有 `actual`(+ 全量覆盖)可进线上成本地板(与 P4 现状一致);`estimated` 仅供报表/建议,不自动改线上计费。
3. **缓存**:按 `(channel, model)` 缓存 CostQuote 到 `as_of`/`valid_until`,避免热路径每请求打服务。
4. **失败兜底**:服务超时/报错 → 回退本地成本,记一条可观测事件,绝不 fail-closed 阻断计费。

### A.5 落地顺序(P5 真正开工时)

1. ✅ 服务侧实现 `:cost` + `cost` 能力位(billing 仓库,`POST /api/v1/internal/billing:cost`;可选 `CostAdapter` 接口,适配器自行声明 `cost` 能力;首个实现:aixhan 从用量账本推导 per-model 单位成本)。
2. ✅ router 侧:CostQuote 客户端 + **只读对账**入口(`GET /:id/billing/cost-quotes`)+ **本地费率缓存**(`channel_model_cost_rates`,经 `POST /:id/billing/cost-quotes/sync` 同步,仅缓存 `actual` 并归一到 CNY)。线上成本地板按 A.4:`BillingServiceCostRateFloorEnabled` 开启后,命中新鲜(TTL)的 actual 缓存则据此抬价,否则回退本地采购路径。**默认关 = 零行为变更**。
3. 灰度:先只读对账(服务成本 vs 本地成本差异上报),确认一致后再**打开** `cost_rate_floor_enabled` 接入线上地板。开启后由 `StartChannelCostQuoteSyncWorker`(master 节点,按 TTL 一半的间隔)自动把各渠道的 actual quote 同步进本地缓存,保证地板不因缓存过期而回退;关闭开关则 worker 空转、缓存不再用于计费。

> 在第 1 步完成前,router 侧不新增客户端代码——避免对不存在的端点写投机/未测的money-path 代码。第 1 步已完成,但第 2 步仍需等**至少一个适配器实现 `cost`**(当前 billing 仓库仅定义了契约与接口,未内置具体 cost 适配器),否则 router 客户端同样是未测的投机代码。
