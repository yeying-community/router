# 部署手册

本文档说明 Router 的打包、部署、健康检查和回滚流程。

## 1. 部署对象

部署对象包括：

1. Linux 主机上的 Router 发布目录。
2. 通过 `scripts/package.sh` 生成的发布包。
3. 通过 `scripts/starter.sh` 管理的单实例 Router 进程。

服务包包含：

1. `build/router`
2. `config.yaml.template`
3. `scripts/starter.sh`
4. `scripts/health-check.sh`

前端另行生成 `router-web` static 制品，部署在 `/opt/deploy/static/router-web/current`。服务和静态制品在同一 manifest 中分别记录，可独立升级和回滚。

## 2. 环境要求

目标机器需要：

1. `bash`
2. `tar`
3. 可执行权限
4. 可访问 PostgreSQL
5. 部署目录允许创建 `logs/` 和 `run/`

服务包构建机器需要：

1. Go 1.22+

前端静态制品构建额外需要 Node.js 和 npm。

如果使用预打包产物部署，目标机器不需要安装 Go、Node.js 或 npm。

## 3. 打包

基于指定版本打包：

```bash
./scripts/package.sh v0.0.1
```

自动选择下一个 patch 版本并打包：

```bash
./scripts/package.sh
```

说明：

1. 默认输出目录是 `output/`。
2. 产物命名为 `router-<tag>-<commit>.tar.gz`。
3. 不带参数时，脚本基于 `origin/main` 打包。
4. 不带参数时，脚本会在本地创建新 tag，并向 `${PACKAGE_REMOTE:-origin}` 推送该 tag。
5. 服务包不包含 `web/dist`；静态包只包含 `web/dist` 的文件。

## 4. 安装

复制发布包到目标机器：

```bash
PACKAGE=router-v0.0.1-abcdef0.tar.gz
scp "output/${PACKAGE}" deploy@your-host:/opt/router/
```

解压发布包：

```bash
PACKAGE=router-v0.0.1-abcdef0
mkdir -p /opt/router/releases
tar -xzf "/opt/router/${PACKAGE}.tar.gz" -C /opt/router/releases
cd "/opt/router/releases/${PACKAGE}"
```

准备配置文件：

```bash
cp config.yaml.template config.yaml
```

至少确认以下配置：

1. `database.sql_dsn`：必填，只支持 PostgreSQL DSN。
2. `auth.cookie_secret`：必须替换模板示例值。
3. `auth.jwt_secret`：钱包登录和 refresh token 依赖该字段。
4. `server.public_url`：密码重置、支付回调和跳转链接需要对外可访问 URL。
5. `cache.type`：只支持 `local` 或 `redis`。
6. `redis.conn_string`：`cache.type: redis` 时必填。
7. `billing_service.base_url`：配置后 Router 调用独立 Billing 服务刷新渠道账务。
8. `ucan.aud`：公网部署或域名/端口非默认值时建议显式配置。
9. `ucan.trusted_issuer_dids`：使用 Node 中心化 TOTP/UCAN 登录时必须配置 Node 当前 issuer DID。
10. `bootstrap.root_wallet_address`：按需配置系统级用户管理自举钱包地址。该配置只用于管理员特权自举判断；普通用户身份以钱包身份 DID（`wallet_identity_did`）为主，钱包地址只是 DID 下的关联链账户。

注意：通过 `scripts/starter.sh` 启动时，实际监听端口和日志目录由 `ROUTER_PORT`、`ROUTER_LOG_DIR` 或脚本默认值控制，不由 `config.yaml` 中的 `server.port`、`server.log_dir` 决定。

## 5. 启动与停止

使用默认端口 `3011` 和默认日志目录 `./logs` 启动：

```bash
./scripts/starter.sh start
```

覆盖端口或日志目录：

```bash
ROUTER_PORT=3011 ROUTER_LOG_DIR=/opt/router/logs ./scripts/starter.sh start
```

常用命令：

```bash
./scripts/starter.sh stop
./scripts/starter.sh restart
```

## 6. 健康检查

发布包内提供健康检查脚本：

```bash
./scripts/health-check.sh
./scripts/health-check.sh --level all --format json
```

检查层级：

1. `liveness`：检查 `run/router.pid` 指向的进程和公开状态接口。
2. `readiness`：在 `liveness` 基础上检查 `/api/v1/public/status` 返回 `success=true`。
3. `dependency`：检查 `config.yaml`、PostgreSQL、Redis 和 Billing 服务。
4. `all`：按 `liveness -> readiness -> dependency` 顺序执行。

常用参数：

```bash
./scripts/health-check.sh --level readiness --timeout 5 --retries 12 --interval 5
./scripts/health-check.sh --base-url http://localhost:3011 --config ./config.yaml
```

依赖检查规则：

1. `database.sql_dsn` 和 PostgreSQL 只读查询是 required。
2. Redis 未配置时返回 `SKIP`。
3. Billing 服务未配置时返回 `SKIP`。
4. Redis CLI 或 PostgreSQL CLI 未安装时返回 `WARN`，不反向要求目标机安装客户端。
5. Billing 服务已配置但不可达时返回 `WARN`，不阻断 Router 基础服务健康。

## 7. Nginx 静态站点

Nginx 从标准静态发布目录读取页面，API 与 Relay 请求代理到 Router。配置示例：

```nginx
map $http_accept $router_html_request {
    default 0;
    ~*text/html 1;
}
server {
    root /opt/deploy/static/router-web/current;
    location / { try_files $uri $uri/ @router_backend; }
    location @router_backend {
        if ($router_html_request) { rewrite ^ /index.html last; }
        proxy_pass http://127.0.0.1:3011;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

此配置优先服务真实静态文件和 SPA 深链接；未命中的 JSON/API/Relay 请求进入 Router 后端，浏览器 HTML 深链接回退到 `index.html`。先执行 `nginx -t` 并确认页面、API、Relay 路由正常，再在 `static-units.conf` 启用 `router-web`。

## 8. 部署验证

部署后按顺序验证：

```bash
cat run/router.pid
./scripts/health-check.sh --level readiness
curl http://localhost:3011/api/v1/public/status
tail -n 50 logs/starter.log
tail -n 50 logs/error.log
```

如果使用了 `ROUTER_PORT` 或 `ROUTER_LOG_DIR`，请替换为实际端口和日志目录。

## 9. 回滚

部署新版本前，保留上一个已验证可用的解压目录。

停止当前版本：

```bash
cd /opt/router/releases/router-v0.0.2-deadbee
./scripts/starter.sh stop
```

启动上一个版本：

```bash
cd /opt/router/releases/router-v0.0.1-abcdef0
./scripts/starter.sh start
```

注意：

1. `starter.sh` 的 PID 文件位于各版本目录的 `run/router.pid`。
2. 回滚前必须先停止当前版本，避免端口占用导致旧版本启动失败。

## 9. 常见问题

1. `config file "./config.yaml" not found`：先执行 `cp config.yaml.template config.yaml`。
2. `database.sql_dsn is required and only PostgreSQL is supported`：检查 `database.sql_dsn` 是否是 PostgreSQL DSN。
3. 钱包登录或 refresh token 失败：检查 `auth.jwt_secret` 是否为空。
4. 执行 `./scripts/package.sh` 后出现新 tag：这是脚本默认行为，不带参数时会自动创建并推送下一个 patch tag。
5. 修改 `config.yaml` 中的 `server.port` 但端口没变：`starter.sh` 会用 `ROUTER_PORT` 或默认值 `3011` 覆盖。
6. 修改 `config.yaml` 中的 `server.log_dir` 但日志目录没变：`starter.sh` 会用 `ROUTER_LOG_DIR` 或默认值 `./logs` 覆盖。
7. `starter.sh` 提示 `Binary not found or not executable`：检查发布目录下是否存在 `build/router`，以及打包过程是否成功。
