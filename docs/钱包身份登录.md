# 钱包身份登录

> 状态：当前实现说明，功能尚未正式上线。
>
> 适用范围：Router 管理后台登录、web3-bs 钱包身份 presentation、Node 身份授权码登录。

## 目标

Router 登录统一收敛到钱包身份，而不是 Passport assertion 或 `subjectId`。

Router 需要的身份信息是：

- `did:yeying:wid_*`：钱包身份 DID，作为外部身份主键。
- `walletAddress`：当前身份已验证关联的钱包地址，用于展示和历史钱包登录衔接。
- `EmailCredential`：Node 签发、Wallet 持有并经用户授权出示的已验证邮箱凭证。
- 可选 `UsernameCredential`：Node 签发的用户名凭证。

Router 当前明确要求已验证邮箱。用户点击钱包登录时，前端向 Wallet 请求 `yeying_identity_presentation`，scope 固定包含：

```text
identity.basic
identity.wallet
identity.email
```

Wallet 若没有 `EmailCredential`，会返回 scope 未授权或凭证缺失。Router 前端应提示用户先在夜莺钱包插件完成钱包身份验证和邮箱验证，再重新登录。

## 有钱包插件登录

1. Router 创建本地身份登录 session，保存 `appId`、`audience`、`nonce`、scope 和过期时间。
2. 前端调用 Wallet 的 `yeying_identity_presentation`。
3. Wallet 在用户确认后返回 identity presentation，包含身份文档、钱包账户 proof 和授权范围内的凭证。
4. Router 后端验证 presentation 的 holder、controller、签名、audience、nonce、scope 和有效期。
5. Router 从 `EmailCredential` 同步 `users.email`，按自动注册策略创建或复用本地用户并写入登录态。

当前实现已经本地验证 presentation 的 Ed25519 签名和上下文。生产前还需要把 `EmailCredential` 的 JWT-VC issuer、JWKS、过期时间和 credential status 校验接入为强校验。

## 无钱包插件登录

无钱包插件时，Router 使用 Node 的钱包身份授权码流程：

```text
POST /api/v1/public/identity/authorize/request
GET  verifyUrl (/identity/authorize?requestId=...)
POST /api/v1/public/identity/authorize/challenge
POST /api/v1/public/identity/authorize/approve
POST /api/v1/public/identity/authorize/exchange
```

Node 的 `verifyUrl` 页面使用设备 Passkey 验证用户。Passkey 只是钱包身份的认证器，不是新的身份主体。Node exchange 返回 `did`、`walletIdentityId`、`walletAddress` 和已授权凭证，Router 不处理 `subjectId`。

这一路径是外部 Web3 应用接入 Node 身份服务的方式，因此 Router 必须配置 `identity.node_url` 和已在 Node 应用中心发布的 `identity.app_id`，并把 Router 回调地址加入该应用的 `redirectUris`。Node 自身作为应用中心时不应依赖这组 Router 配置；Node 管理端登录使用钱包签名 / UCAN 自举登录，避免“必须先发布 Node 应用才能登录发布应用”的循环。

## 不再使用的概念

以下概念不得进入新的 Router 登录契约：

- Passport assertion
- `subjectId` / `sub_xxx`
- Router 侧 Passport binding 表
- 把钱包地址、邮箱或用户名作为长期身份主键

Router 可以继续保留“通行证登录”的用户入口文案，用于描述无钱包插件场景，但内部行为必须是钱包身份授权码登录。
