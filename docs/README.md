# Router 文档入口

本目录用于沉淀 Router 的当前架构、接口规范、运营规则和阶段规划。
文档治理目标是：当前真源清晰、专题边界清晰、历史材料不干扰日常阅读。

## 治理规则

1. 当前实现口径优先写入“当前真源”，阶段性材料优先合并到 V1 / V2 / V3 或直接删除。
2. 涉及 API 变更时，必须同步更新 [OpenAPI](./openapi/router.openapi.yaml)。
3. 涉及架构边界变化时，必须同步更新 [路由架构 V1](./路由架构V1.md)、[路由架构 V2](./路由架构V2.md) 或 [路由架构 V3](./路由架构V3.md)，并更新必要的专题文档。
4. 专题文档不重复罗列接口明细，接口明细以 [OpenAPI](./openapi/router.openapi.yaml) 为准。
5. 文档中的代码路径统一使用仓库相对路径，避免写绝对路径。
6. 涉及兼容或历史字段时，必须明确当前是否仍生效、是否仍会写入、计划是否移除。

## 提交前核对

1. 路由是否存在：对照 `internal/transport/http/router/api.go`。
2. 字段是否存在：对照 `internal/admin/model/*` 与 controller 返回结构。
3. 页面行为是否一致：对照 `web/src/pages/*` 和 `web/src/components/*`。
4. 规划是否冗余：确认已完成事项已从 [路由架构 V2](./路由架构V2.md) 或 [路由架构 V3](./路由架构V3.md) 移出。
